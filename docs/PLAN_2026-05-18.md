# Migration Plan - 2026-05-18

This plan addresses issues raised in the PR comments, focusing on moving towards a "Runtimeless" architecture and improving the infrastructure organization.

## 1. Refactor Search to VTL
The current search functionality is implemented via a Lambda function. To follow the "VTL Over Lambda" mantra, we will reimplement this using direct DynamoDB Scan integration in API Gateway.

- **OpenAPI Changes**: Update `/search` endpoint to use `type: aws` with DynamoDB Scan.
- **CDK Changes**: Remove `SearchHandler` Lambda and related permissions.

## 2. Separate Website and API Stacks
To improve maintainability and follow the owner's suggestion, we will split the CDK stacks.

- **TransSchemaApiStack**: Will contain DynamoDB tables, Cognito User Pool, and the API Gateway.
- **TransSchemaWebsiteStack**: Will contain the S3 Bucket for static assets and the CloudFront distribution.

## 3. Cleanup Unused "Server" Code
As all logic is being moved to VTL and managed services, the `server/` directory is no longer needed.

- **Removal**: Delete the `server/` directory entirely.
- **Logger**: Since the custom logger was only used by the Lambda, it will be removed as well.

## 4. Native AWS Auth
Confirm that Cognito is used for authentication as requested. The current OpenAPI spec already uses `CognitoAuthorizer`.

## 5. API Spec Validation
Verify that `docs/openapi.yaml` covers all required schema and translation capabilities.
